# Technical Reference Index

快速 look up:endpoint / DB / env var / iOS 模組 / ops 腳本叫什麼、定義在哪。
新增 router / table / env var / ops 腳本時,**同 PR 內補一行**。

## Reconciler poison cooldown

`ops/kg_reconcile.sh` 的 `KG_RECON_POISON_COOLDOWN` 以十進位解析；前導零（例如 `09` / `08`）與空值、非數字值都不會被 Bash 八進位規則誤解，非法設定會維持 poison 的 fail-closed 冷卻狀態。未設定時使用 3600 秒預設值。

## Review receipt exemption depth

`ops/review_audit.sh` 的 `single-line-small-file` 不是只驗 trailer：工具會拒絕 merge commit、超過一行增刪、binary diff，以及新增行含規範性語彙；`trivial-typo` / `rename-only` / `format-only` / `generated-snapshot` 維持 trailer-only。`machine-repair` / `backlog-grooming` 仍由工具檢查路徑；前者可包含 backlog ledger JSON 與本次 reanchor 實際改寫的 `docs/**/*.md`（generated view 除外），後者仍只允許 backlog JSON。

### docs impact control

`ops/docs_impact.py` 的 `--surface-paths` 逐字輸出 `docs/registry.yml` 的 `agent_facing_surface.paths`；`--surface-scan <pattern>` 以內建 regex 走訪該清單（含 `.claude/`）並輸出 `SURFACE path:line:` 命中；`--root <dir>` 供 fixture 或隔離樹指定根目錄。缺少清單或清單路徑不存在時 fail-closed。

## Environment Variables

完整清單見 `docs/sop/deploy.md`。此處列分組與代表項:

- **Secret encryption**: `SECRET_ENC_KEY`(可選)— `secret_store.py` 對 `enc:` stored secret 的對稱加密根金鑰,`sha256(SECRET_ENC_KEY)` 派生 Fernet key。**未設時 fallback `sha256(JWT_SECRET)`**(既有部署零破壞)。設了它後,**輪換 `JWT_SECRET` 不再令 stored secret 無法解密**(兩者脫鉤);解密採多金鑰容錯(當前 key 先試,失敗退回 legacy `sha256(JWT_SECRET)`),過渡期無需 re-encrypt migration。

### backlog wave filing

一般裸 `backlog.py add` 立即寫入 store；批次 worker 發現新問題時用 `backlog.py add --stage`，只 append 到共用 gitignored queue，由整合者落地後以 `anchor --commit` 實體化。queue 內同一 ready id 出現多列（add/add、add/closure）時 anchor 全波拒絕且不消費任何 row，避免列序覆蓋證據或狀態。

`backlog.py reanchor` 預設只處理孤立的 `fixed_by`；`reanchor --docs` 另掃 `docs/**/*.md` 的
`verified_against` sha，沿用同一個 `git patch-id --stable` 唯一匹配證據。結果以 `doc_plan` /
`doc_unmatched` 明列，零或多個候選一律不猜；只有 `--commit` 才以原子寫入改檔。cutover 的
post-landing repair 會帶上 `--docs --json`，並把工具回報的實際文件路徑與 backlog ledger 一起納入
machine-repair commit，避免留下 tracked dirty docs。

`C.UTF-8`,於是同一支腳本「人跑」與「gate 跑」走不同解析路徑——`devops.sh:669` 的 `$dest（` 因此手跑 8 次全綠、經 orchestrator 4/4 全紅。選 `C.UTF-8` 是因為它就是 gate 今天實際跑的值,且較嚴格(會抓到寬鬆環境放過的東西)。**同時移除繼承來的 `LC_ALL`**:POSIX 讓 `LC_ALL` 蓋過所有 `LC_*`,留著會讓這個「選擇」在呼叫端剛好設了 `LC_ALL` 時變成無效的裝飾(實測 `LC_ALL=C LC_CTYPE=C.UTF-8` 的 effective ctype 是 `C`);代價是其餘 category 回退到呼叫端自己的 `LC_*`/`LANG`,而它們都不影響 shell 如何 tokenize。`env=` 整組取代環境時同樣套用此決定。heartbeat 另含 **`stalled` / `outBytes` / `idle`**（IMP-20260805-bc8315）：`alive=true` 只證明「程序存在」，`outBytes`（累積 child 輸出 bytes，**stdout + stderr 合計**）才證明「程序在前進」，`idle` 是**上次真的吐出 byte** 至今的秒數（在觀察到的當下取時戳，不是在 heartbeat 印出時才補記，否則會系統性低估真實靜默達一整個間隔＝預設 20 秒），滿一個 heartbeat 間隔沒有任何新 byte 即 `stalled=true`。三個新欄位**一律追加在既有 `alive` 之後**，欄位名與順序不動——下游（`ops/tests/test_ios_ops_release_heartbeat.sh`）匹配的是未錨定的 `... pid=N alive=true` 前綴。本層**只暴露不自動 kill**：呼叫端自行決定，要硬上限仍走 `timeout_seconds`；「正常但安靜」（純等鎖、慢下載、**child 還沒啟動完成**——啟動慢於一個間隔時首拍必然 `stalled=true`）是合法狀態，把 `stalled` 接成 fail 需該呼叫點自帶「安靜期有界」的實測證據。注意 `stalled=` 這個 token 在 `ops/worktree_orchestrate.py` 的 `[worktree][land] phase=waiting` 行另有一個**同名不同型**的用法（那邊是秒數，這邊是 bool），兩者靠 `phase=` 區分，寫 grep 時務必錨定 phase 而非只找 `stalled=`。stdout/stderr 以獨立 reader 持續 drain（用 `read1` 而非 `read`：後者會阻塞到滿 64 KiB 或 EOF，低流量 child 在退出前對 parent 完全不可見，會讓所有低流量但正常的 child 誤判為 stalled），只保留 bounded tail，保留 child rc、signal 與分離 stderr 語意。child 另開 isolated session；parent 中斷或 deadline timeout 會對整個 process group TERM，逾期 KILL，timeout 固定回 rc 124；即使直接 child 已先退出，只要孫程序仍持 inherited pipe 也會清掉整個 group。`worktree_orchestrate.py` 的所有 shell gate，以及潛在長時 mutation / network probe（fetch、worktree add/remove、rebase、merge、push、ls-remote、branch teardown、committed sweep）都必須走此 runner；只有本機、預期快速的 parsed-output probe 可走 silent capture。`app_review_evidence.py` 的 desired shape/build/bundle、journey、physical demo、gate evaluation亦使用同一原語；`ios_ops.sh workflow release` 的 project settings、Organizer、TestFlight、ASC versions、App Review gate 五個來源也由 `ios_ops_stream_capture` 接線，stdout 保持單一 workflow JSON。測試：`ops/tests/test_streaming_command.py`、`ops/tests/test_worktree_orchestrate.py`、`ops/tests/test_app_review_evidence.py`、`ops/tests/test_ios_ops_release_heartbeat.sh`。

### `worktree_orchestrate.py` parallel round control

Campaign reservation 是多票並行的 registry control plane：`campaign-reserve` 以 `kg.worktree.campaign.v1` request 在 canonical ledger lock 內重驗 local-main base、coordinator、partition quota、完整 ticket set、structured write sites、blocked/co-land 與既有 claims，通過才原子寫入 `.cache/worktree_campaigns/<campaign-id>.json` 與 registry 的 `campaign_reservations`。child 以 `open --next-backlog --campaign <id> --partition <id>` 從指定 partition 逐票轉成 active claim；普通 `open --next-backlog` 排除所有尚未轉移的 reservation。`read/read` 同 path 可共存；write/write 或 write/read 只有雙方具名不同 symbol 才縮小 collision，未知 path/mode 與未具名 overlap 一律拒絕。CLI 與純 validator 的 machine schema 由 `ops/lib/worktree_campaign.py` 與 `ops/tests/test_worktree_campaign_reservation.py` 共同釘住。

同步協調者以 `open --next-backlog` 在 canonical registry lock 內完成 dispatch-head 選取＋獨佔登記；明示 `--backlog` 同樣重驗 unresolved `blocked_by`，`register --exclusive` 讓同 branch/path 的第二次 birth fail closed。`register` 在 worktree 尚未出生、且 ledger 不在 repo 內時，必須由 orchestrator 傳入實際 `--repo-root` 解析 claim-time base，禁止從 arbitrary state path 猜 repo。`integrate` 會以 hand-back SHA 原子保留來源給單一 integration owner；具名 ticket batch 以 `hand-back --outcomes <json>` 交回逐票 acceptance/outcome，registry 產生帶 identity/base/tip/digest 的 seal，`integrate` 對缺 seal 或不整合 outcome fail closed（`--allow-unhanded` 只保留 legacy/imported 的明示警告路徑）。每個 slug 的 start/continue/abort 由獨立 flock 序列化，state 以 atomic replace 寫入。尚有其他 session 或尚未取得 develop 授權時，fresh／continue 一律 `--no-gate`，純組裝完成後 integration tree 也 commit + hand-back。有授權且 base 仍新鮮時，最終 integration tree 以 `--continue --commit` 跑唯一 Gate；base 已前進時，須 abort、核對來源 hand-back tip、明示 teardown，再由新 main fresh `integrate --commit` 跑唯一 Gate。pass/warn 後移入 `worktree_integrations/completed/<slug>-<head>.json`。Gate BLOCK 保留可續 state，修正後同命令只重跑 Gate，成功子 gate 的重用仍受下節 input fingerprint 契約約束。兩輪原子收斂採 round integration branches → hand-back → parent integration → parent Gate → 單一 cutover；未落入 base 的 integration ref 不得用 `resolve --via-integration` 授權拆來源，且 integration tree 在其 source records 仍 active 時不可先刪。

### `worktree_orchestrate.py` gate input reuse

`gate` 的 verdict 仍綁當前 HEAD、base 包含性與 orchestrator 身分；同一工作樹追加變更時，只有責任
輸入集合與內容指紋未變的 `pass/warn` 可重用。record 與 `cutover` payload 會列出來源 HEAD、輸入
檔案、指紋與 rerun 理由；未知 scope、legacy record、輸入或定義變動、`block`/`inconclusive` 來源
一律重跑。這是成本最佳化，不是跳過 fresh-HEAD 安全護欄。

iOS 可執行 gate 的 input scope 依 command delegate 分離：`ios-build` / Catalyst 雜湊 iOS tree、
`ios_ops.sh` 共用載入面與 build runner；unit/UI/live-demo compile 改雜湊同一共用面與 test runner。
因此只修 `ios_test.sh` 時可重用已綠 build，改共用 dispatcher/helper 時兩者仍重跑；未具名的新
iOS gate 保守退回完整 iOS surface，不能自行取得窄 scope。

空 diff 仍可合法重跑，但 gate record 會以 `no_changed_files=true` 明示「沒有變更路徑被驗證」；人讀輸出會警告，`--receipt-line` 會加 `no-changes`，避免把合法 re-gate 或錯樹空跑誤讀成新修改已被驗證。

linked worktree 的 gate record 另含 `primary`、`primary_dirty`、`primary_dirty_error`；primary 有未提交 tracked 檔時只在人讀輸出具名警告，不改 gate verdict 或 exit code，避免把共用 primary 的合法並行工作誤擋。

每道 gate 的結果與 append-only `history.jsonl` 另帶 `machine_state`：判決前後的 load average、active worktree 數、以及偵測到的 `xcodebuild` / `ios_test.sh`（只保留 PID＋類型，不保存 raw argv）。`ios-test-unit`、`ops-shell:test_ios_test_discovery.sh` 與 `ops-ci-coverage` 判紅且觀測到同機 iOS 工具鏈行程時，summary 會列出「可能不可重現」的污染警告與安靜狀態重跑命令；verdict 仍是 red，沒有自動 retry，因為這是歸因證據而非放寬 gate。

| `Ticket Factory` / `Delivery Team` / `Integrator` | 一個 Ticket Factory thread 批量產出 groomed tickets；多個 Delivery Team thread 各自取得不重疊 batch，由 Integrator 派 N 個 child worktree、incremental fan-in，最後 `close-wave --commit --sync` 完成 primary＋remote。角色視野與未知升級唯一以 `docs/reference/agent_context.md` 為準；詳細 worktree 動詞與停止點唯一以 `.claude/skills/worktree-flow/SKILL.md` 為準；backlog 狀態唯一以 `./ops/backlog.py lifecycle --json` 為準。正常溝通以 registry/state/receipt；不穩定才用內建 thread message，欄位契約以 worktree-flow 為準。 |
| `integrate --campaign <id> --parent` | Parent-only fan-in：在建立整合 worktree 前，於 registry lock 內對帳 campaign 的每個 partition 恰一個 child receipt（manifest digest、tip、ticket set、typed outcome seal）；缺漏、重複、foreign、stale 或第二 owner fail-closed。成功後自動產生固定 source queue；完成 manifest 保存每票 source/child/parent SHA 與 outcome/acceptance/closure。手動 `--branches` 維持相容，兩種模式互斥。 |
| `backlog.py acceptance feedback` | `acceptance_cmd_static` 是選填、60 秒內的唯讀 worker feedback；`verify <id> --static-only` 只跑這個子集。`update`、`stage`、`anchor --commit` 結案仍只跑完整 `acceptance_cmd`。 |
