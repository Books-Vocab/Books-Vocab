## Core numbers — overfit metric

Every hard-coded literal is classified by how it can be *re-derived* by the engine:

| class | meaning | records | % |
|---|---|---:|---:|
| **token** | literal == a `kg-tokens.css` scalar (pure L1 token→token) | 631 | 70.2% |
| **L2_candidate** | non-token literal recurring in ≥2 surfaces → codifiable platform delta | 159 | 17.7% |
| **orphan** | non-token literal in exactly 1 surface → suspected overfit | 109 | 12.1% |

**Token-explicable: 70.2%** · **L2-rule-explicable: 17.7%** · **orphan / overfit: 12.1%**

Interpretation: ~70% of all measured geometry is already a pure token lookup the
engine gets for free (L1). ~18% recurs across surfaces — these are the systematic
platform deltas worth codifying as L2 law. The remaining ~12% are single-surface
orphans: either genuine page-specific anchors (a nav title's measured top) or
overfit residue. **Orphan % is the engine's overfit budget** — the L3 holdout loop
must keep it from leaking into the codex.

Cluster-level: 130 token clusters, 19 L2 clusters, 88 orphan clusters.

## Method notes

- Token classification resolves `var()` aliases one hop through the token table,
  then matches the literal px/unitless scalar. `em`/`rem`/`%` excluded (relative,
  not pixel deltas). `opacity`/`z-index`/`flex` skipped (structural primitives).
- A cluster keys on (normalized prop-class, literal). `font-weight: 700/600/400`
  cluster widely because ElmsSans ships 400/700 only and Songti has no usable Bold
  face on Chromium — the canonical typographic platform delta (L2).
- `measured?` = the nearest comment block contains the literal string `measured`,
  the convention the parity author used to flag a value derived from pixel diffing
  rather than a token. These are the highest-confidence L2 inputs.
